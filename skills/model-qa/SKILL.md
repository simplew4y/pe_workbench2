# 模型追问

仅复用 `skills/investment-framework/SKILL.md` 中的取数、证据、计算、口径与核验规则，不继承其报告、analysis-state.json 或 framework_commit 交付要求。宿主每轮通过 `lib/turn-context.mjs` 注入问答协议与文档输出规则。

普通问答和追问直接在聊天中完整回答，不自动保存 QA 报告。仅在用户明确要求文档/导出/保存，或正在执行用户已授权的投资框架交付阶段时才生成所需文件。仅仅提及投资框架、分析已有报告、前一轮生成过框架，不构成本轮生成文档的授权；“只在聊天回答/不要文档”优先。明确要求修改已有文档时只修改该文档，不额外生成一份 QA 报告。

- 假设解释：追公式来源，对齐单位、期间，区分区块内同名指标。
- 敏感性：沿真正输入传播，调用 model_whatif 或明确「局部」范围；派生数调用 calc。
- 比率：报告占比/增速/倍数前必须调用 `ratio` 或 `calc`，禁止心算；以 NAV 为分母的占比必须声明 `valuation_basis`（pre_discount/post_discount）。
- 证据：预测不等于兑现，多篇转述不算独立证据，单期不证明连续多期。
- 代码：查询 Cover/元数据；未命中报告 coverage，不等于不存在。
- 失效条件：阈值无依据写「待定」及 calibration；区分短期修订、置信度调整和机制失效。
- 更正：使用台账当前值，不复述已被替代的数值。
- 负向依赖结论：先 workbook_trace mode=path，交代解析覆盖限制。

## 目标价 / 偏离

- `G*` / `gaps[].id` 只是缺口 ID，不是单元格；禁止“目标价单元格（G1）”“没有独立目标价单元格（G1）”。
- 问目标价、偏离、上行空间：先取模型目标价（当前 `valuations` 的 `V*.output=target_price`、`workbook_trace` 估值输出格、或明确 `target_price` locator），再 `westock_query` 现价；首句同时给模型价、现价、空间。
- 负向“没有目标价”结论前，必须先 `workbook_trace` 覆盖估值输出路径；语义检索 miss ≠ 不存在。
- 禁止用“先纠正前提 / 无法精确回答”挡掉；读失败写 `unverified` + gap，会话或状态已有可读目标价必须使用；券商目标价只作对照附录。

## 自查协议（十倍错 / 数字复核）

用户说「自查」「检查前面」「有没有十倍错」「全部正确吗」时，按以下顺序执行，不得跳步：

1. **先检索**：调用 `transcript_search`（同时返回 `ledgerMatches`：用户主张 / 更正 / 事实）。不得凭记忆或只扫助手正文。
2. **列候选人**：逐条列出命中项（角色、轮次、主张值）；没有命中就写「未发现候选人」，不得写「全部正确」「没有十倍错误」「没有少写十倍」。
3. **金额必换算**：每个金额候选逐条调用 `unit_convert`（百万元 ÷ 100 = 亿元）或 `calc`，并对照模型单元格；禁止心算。
4. **输出表**：至少含 `角色 | 主张 | 应为 | 依据` 四列；结论写「核对 N 条后均与单元格一致」或列出不一致项，不写绝对「全部正确」。
5. **写入台账**：用户口述「写成了…」「应为…」「有人写成…」时，先 `ledger_record` `kind=claim` 记录 user_claim；确认后 `kind=correction`（可带 `claimId`）作废旧值，不删除旧条目。不要把用户长文里的所有数字自动入库。
