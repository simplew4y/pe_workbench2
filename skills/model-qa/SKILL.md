# 模型追问

遵循 `skills/investment-framework/SKILL.md`；宿主每轮通过 `lib/turn-context.mjs` 注入相同协议。

- 假设解释：追公式来源，对齐单位、期间，区分区块内同名指标。
- 敏感性：沿真正输入传播，调用 model_whatif 或明确「局部」范围；派生数调用 calc。
- 证据：预测不等于兑现，多篇转述不算独立证据，单期不证明连续多期。
- 代码：查询 Cover/元数据；未命中报告 coverage，不等于不存在。
- 失效条件：阈值无依据写「待定」及 calibration；区分短期修订、置信度调整和机制失效。
- 更正：使用台账当前值，不复述已被替代的数值。
- 负向依赖结论：先 workbook_trace mode=path，交代解析覆盖限制。

## 自查协议（十倍错 / 数字复核）

用户说「自查」「检查前面」「有没有十倍错」「全部正确吗」时，按以下顺序执行，不得跳步：

1. **先检索**：调用 `transcript_search`（同时返回 `ledgerMatches`：用户主张 / 更正 / 事实）。不得凭记忆或只扫助手正文。
2. **列候选人**：逐条列出命中项（角色、轮次、主张值）；没有命中就写「未发现候选人」，不得写「全部正确」「没有十倍错误」「没有少写十倍」。
3. **金额必换算**：每个金额候选逐条调用 `unit_convert`（百万元 ÷ 100 = 亿元）或 `calc`，并对照模型单元格；禁止心算。
4. **输出表**：至少含 `角色 | 主张 | 应为 | 依据` 四列；结论写「核对 N 条后均与单元格一致」或列出不一致项，不写绝对「全部正确」。
5. **写入台账**：用户口述「写成了…」「应为…」「有人写成…」时，先 `ledger_record` `kind=claim` 记录 user_claim；确认后 `kind=correction`（可带 `claimId`）作废旧值，不删除旧条目。不要把用户长文里的所有数字自动入库。
