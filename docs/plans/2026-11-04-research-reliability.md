# 线上研究回复共性问题修复

基线：simpleway/main 80895145a6159ebe56408a4dfd305f10f61333b5。origin/main 落后，原工作区有用户修改；使用隔离 worktree / codex/research-reliability。不部署、不改线上数据。

PLAN 方向合理，按七个机制实施：确定性计算与单位；精确查询与图可达性；只读副本 what-if；逐轮研究协议；会话纠错与历史检索；状态语义校验；答后可疑完整性提示。

修订：
- 答后检查只提示，不自动续写、改写答案或更改模型数据。
- 日期不能证明财报是否披露；证据类型、持有期间与预测期间分别表述。
- 图中无路径只说明解析图中未发现，不能证明真实模型不存在依赖；角色仅按公式/常量机械分类，不猜测经济含义。
- LibreOffice 情景必须分别重算基准与修改副本、报告缓存漂移，不能承诺 Excel 等价；缺引擎或无原文件即明确失败。
- 未校准阈值允许 pending，必须附校准计划，不能成为活动监测。
- 纠错须有来源，台账本身不是已核实事实；不自动回写旧产物。

验证：先固定十个受控回答用例（R01–R10）和十组机制测试，再实施。原附件缺少 Excel 原件及 PLAN 所述完整 replay 脚本，因此用归档解析图、短上下文进行受控复现，不冒充原 100 轮前缀重放。同一模型、温度、问题、证据来源；基线与修复后各一次，不能估计稳定通过率。原答错误与受控基线表现分开记录。工具能力变化是被测变量。

验收：十组离线回归通过；现有相关 suites 通过；真实模型调用产物保留（失败也保留）；独立只读审查后修复复验。原 Excel 重算与线上 UI 集成没有证据时明确未验证。

## 执行结果

首批工具与宿主机制已实现，详细人工评分及完整回答/工具证据在本地 `out/reliability-eval/修复与十例对比报告.html`（私有原始证据，不入库）。十例短上下文最终7通过、2部分通过、1不通过；R01仍有收益基准错误，R10有新增解释错误，不能宣称全部解决。18项机制/集成回归通过；独立审查的SDK消息投影P1已修复并独立复验。工作簿测试2项EMF警告失败在原基线同样存在，原预期保留。

复现脚本使用 `EVAL_SOURCE` 指向用户归档的 `source/2026-11-03`，`EVAL_ENV` 可指定本机环境文件（或通过环境直接提供DEEPSEEK_API_KEY/PI_MODEL），`EVAL_OUT` 指向隔离评估目录。运行 `node scripts/eval-reliability.mjs before` 必须在修改前产品代码上；固定cases与配置不能通过覆盖旧结果冒充新实验。`after` 是对照运行；它是受控API适配器，不替代真实SDK测试。测试命令为 `npm run test:reliability`；此套包含Python/openpyxl与真实LibreOffice合成回归，缺依赖会明确失败而非静默跳过。

尚未验证：浏览器目视、生产服务、原Excel复杂模型重算/原生Excel等价、完整100轮上下文、跨fork台账继承。未推送、未合并、未部署。
