## 交付边界

本批完成一个兼容现有系统的持久化闭环，**不是最终方案全部 S0–S4 完工，也不是所有自然语言数字回答准确率已达标**。

已实现：真实工具结构化结果 → 先保存事件 → 来源版本/证据/事实 → 项目级查询 → 新会话复用 → 明确版本的计算 → 不可变框架修订 → 可恢复导出。保留旧台账与报告，不自动迁移、不自动提升旧数据的可信度、不绕过模型/产物修改审批。

## 复用与新增

- 复用 `store.db` / `data/workbench.db`，沿用既有 SQLite 存储、材料版本和 blob SHA256，不新增数据库服务。
- 新表统一 `fm_` 前缀：`fm_schema`、`fm_events`、`fm_sources`、`fm_evidence`、`fm_facts`、`fm_calculations`、`fm_frameworks`、`fm_outbox`，第三批增加 `fm_imports`。
- 每个查询/写入都绑定服务端项目 ID；工具不接受项目 ID。版本载荷不可变，生命周期和发布状态单独记录。
- 精确数值复用 `calc-tool.mjs` 的 BigInt 分数运算。保存原值/原单位、十进制规范值、乘数和币种；不把空白/横线转成零。
- 旧 `.pi/ledger/<session>.json` 和 topics 仍可读，继续保留会话主张、纠错、待办及原审批；启用项目事实库的回合不再把旧 topics 数值摘要或仅按值匹配的旧纠错当作数字真值注入。新项目事实没有从旧 JSON 自动导入，旧数字不会因迁移而变成 source_checked。

## 实际调用路径

1. `server/project-context.mjs` 创建 `FactMemory`，建表并恢复 received/failed 事件和 pending 导出。启动时 started 但未收结果的事件标记 interrupted。
2. `session-service.mjs` 为工具构造会话专属捕获包装器，metadata 包含 session/run/turn/actor。`workbook_query`、`workbook_trace`、`pdf_read`、`calc`、`ratio`、`unit_convert` 的成功结果先落事件，再在事务内适配。失败工具结果不登记事实，持久化失败对模型可见。
3. Excel citations 保留公司、指标、期间、口径、实际/预测/假设、情景、币种、原单位、SHA、原文及缓存公式标识。解析器仅采用明确标签，例如 `company: ACME`、`consolidated`、`2024 actual`，不凭文件名或过去年度猜身份。
4. PDF pages/search/tables 返回真实页码与文本证据。第二批加入显式页标签/对齐表头语义取数，含脚注/冲突/不完整上下文仍待核；`fact_bind` 仅允许证据中存在的数值，人工/模型补注仍保留 needs_review。
5. `validate_state` 仅验证结构，`verifiedFacts=[]`，输出 candidateFacts 和 `factVerification=not_performed`。不会再把估值假设或旧值自动登记成已核事实。
6. 新会话通过 `fact_query` 检索；回合上下文放入有限项目事实摘要，源文仍是数据而非指令。没有命中、存在歧义、存储失败和来源过期分别返回不同状态，允许回查原文件。
7. `fact_correct` 要求事实 ID、预期版本和完整身份。新值为待核用户主张，保留理由，旧版本不删除，派生记录/框架失效。不会修改源模型和原研究文件。
8. `fact_calculate` 固定两个输入版本，支持 ratio/add/subtract/multiple，拒绝隐式跨币种、期间、主体和口径计算，记录公式、舍入、单位转换与输出。输入变化使下游失效，不自动重算全部模型。
9. `framework_commit` 校验引用存在/质量/生命周期与预期框架版本。DB 同一事务写快照和 outbox。JSON/Markdown 写入 `exports/fact-memory/<framework_id>/rN/`，两个文件完成后才更新 DB 发布状态。中途失败旧发布版仍可用，恢复只重试导出，不新增修订。
10. `fact_query action=framework` 校验发布文件内容 hash；手工改动不会反向覆盖事实。普通 read/write/edit 实际路径受项目限制，直接写内部台账和发布目录被拒绝，包括现有符号链接别名。

## 状态与限制

- `quality` 与 `lifecycle` 分开。source_checked 仅表示结构化来源支持提取的数字及身份，不代表商业判断绝对真实。
- 缺主体/期间/口径/币种、来源不完整、公式缓存未重算、PDF 补注、后台读数保留 needs_review。预测也可以 source_checked，但 basis_type 仍是 forecast。
- 独立来源冲突保留，返回 ambiguous；只在同材料更新或 ID 定向更正时替代对应版本。后台候选不会取代前台已核值。
- `fm_events` 处理状态可由 `fact_query action=health` 查看。接收结果后入库失败可重放。进程在结果尚未送达/接收记录尚未成功时崩溃，只能报告 interrupted，不能声称保存了未收到的数据。
- 当前查询按项目注册事实检索，不是全文件覆盖；上下文预览最多 20 条，工具每页最多 100 条并报告截断。没有新增向量索引或跨项目索引。
- 旧正文自然语言 lint 保留，新增身份/单位/预测检查和严格结构化 claim 校验。自由文本检查是保守规则，不等于完整语义验证；别名、指代和复杂比较仍需模型与后续验收。
- 框架提交第二批升级为 `numeric_validation=bound_fields_and_report_tokens`，验证数值字段/正文片段的精确事实绑定，报告通过宿主模板渲染。发布仍不证明自然语言论证正确，也不代表原资料披露内容绝对真实。
- 后台使用同一捕获服务，但仅产生待核候选；没有自动事实晋级/发布、全依赖图重算、离线整理或自动旧台账导入。
- 暂未将任意 read/write、web、行情等所有来源输出接入项目事实适配器；它们不能被算作本批持久化覆盖。

## 第二批补充实现与验收

本批新增字段级发布闸门与保守 PDF 语义抽取，不改变 SQL 事实层权威，不自动覆盖旧报告。

- `framework_audit` 枚举结构化状态的业务数值叶子和正文数字片段。`numeric_bindings` 使用 JSON pointer（正文加 start/end）绑定完整身份和精确事实版本。元数据只在符合类型时排除；嵌套对象中的数字仍须绑定。
- `framework_commit` 在同一事务中重验绑定、值/单位/币种/期间/指标/实际预测、冲突和生命周期。报告只允许受控 `{{fact:/pointer}}` 引用，宿主输出事实含义、币种、状态与版本。未绑定裸数字包括全角数字阻断发布。该门禁不证明自由文字的研究结论或逻辑正确。
- `pdf_read` 保存原始页/表证据，并提取显式元数据的数值行和对齐多期间表头。金额币种、actual/forecast/assumption 不相互覆盖；括号修饰、尾注、脚注、冲突标签、跨页缺表头、截断和扫描一律待核或仅存证据。未知复杂 PDF/OCR 不做猜测。
- Excel 数字型百分比未提供编码时不自动晋级，防止 0.2 误当 0.2% 而不是 20%。仍须补真实模型百分比格式映射与重算。
- 同一来源版本里不同位置的冲突值共存，不因后读覆盖前读；只有更新来源版本可替代。

## 第三批：旧数据兼容与故障恢复

新增 `fact_maintenance`（后台会话仍只有只读 `fact_query`）：

1. `action=preview_legacy, session_id=...` 读取当前项目旧台账，返回 SHA256、数值候选/跳过数量、已有批次状态。拒绝路径穿越和符号链接，限制文件大小与旧格式版本。
2. `action=import_legacy, session_id=..., expected_sha256=...` 仅导入该版本；同会话同 SHA 幂等，整批事务。原记录/台账快照保留；主张和更正不会自动变成事实，所有数值为 needs_review。原状态 stale_source、过期、已被纠正或需核对更正归属的旧值保留 stale。
3. `action=rollback_legacy, batch_id=...` 只把该批次精确导入版本失效并向派生/框架传播，保留历史载荷与后续用户定向更正版本，不删除源文件。不自动重新激活已回滚 SHA。
4. `action=rebuild_index` 从现有事实行重建 `fm_facts_current` 并执行 SQLite 完整性检查，不改事实载荷。它不是丢失 DB 后从报告恢复真值的工具。

导入后台账内容变化、来源材料换版、行情到期会再次触发失效检查。旧格式更正无法可靠确认身份时保守待核/失效，不猜测新值对应主体。

`test-fact-maintenance.mjs` 验证预览只读、SHA 冲突、幂等、项目隔离、路径/符号链接边界、原文件字节不变、保留后续更正、框架失效、旧失效格式、事务失败回滚和索引重建。
`test-fact-memory-crashes.mjs` 使用真实独立 Node 进程与 SIGKILL，覆盖开始但未收到结果、已接收未规范化、规范化/导入事务中、框架 DB 已提交未导出、仅第一个导出文件完成、两个导出文件完成但未发布。恢复不产生重复事实/修订，发布前旧视图继续可用；双进程相同期望修订只有一个提交，另一个 revision_conflict。

这些是进程崩溃测试，不是断电/磁盘损坏/文件系统 fsync 耐久性验收。真实业务 S4、360题、30次拒答、模型 token/延迟成本、LibreOffice 全链路与高负载仍需对应数据/环境，不能以确定性测试替代。
