# 报告反复审校：证据链、修复与离线验证

## 结论

本轮已经定位并修复一条可以由记录直接证明的返工链路：**成功计算回执被审校输入选择丢弃 → 审校把输入不足当成报告缺证 → 主模型重写报告 → 审校再次因输入遗漏或新引入的口径问题拒绝**。另一个确定的耗时放大器是审校输出截断：原记录六轮报告审校实际发起了十一次模型请求。

本轮完成的是代码修复和离线机制验收。没有生成新的金融判断，没有重新发起付费问答，不能宣称附件题已完整答对或真实耗时已经降低到某个值。

## 已确认的根因与修复

### 1. 证据排序仍把计算回执当普通文本

首次报告审校的 `evidenceCoverage.omittedIds` 明确包含当时全部 9 次成功的 `model_whatif` 调用。原始回执有输入单元格、扰动值、重算前后结果与 `recalculated:true`，并非只有成功标签。第二轮审校的理由又明确写到“相关调用未包含或仅有截断”“本次输入未覆盖其计算链”，但把它作为金融问题要求改稿。

旧排序依赖词语匹配和长来源的优先级。计算回执只写单元格和结果，业务名称却写在报告里，所以容易落后于长篇工作簿/网页。

修复：本轮成功执行的计算和明确复用的旧计算按原子回执优先分配空间，随后安排显式来源、概念相关来源及其他记录。保留请求参数、结果、来源身份和失败信息，不按相同数字认领证据，也不沿用上轮通过结论。旧的无关计算不因历史上成功就永久占据最高优先级。

检查中还发现：仅独立运行选择器会漏掉真实入口额外传入 `sourceIds` 的竞争。现已增加“实际审校输入必须包含这些回执”的断言，并用全部六次真实报告提交验证。

### 2. 结构化输入重复携带长工作表摘录

部分计算结果把同一工作表的大量行标题反复放入每个绑定变量的 `excerpt`。直接完整复制这些字段会再次吃掉预算，导致修复计算证据后又丢掉被引用的来源。

修复：保留变量的来源 ID、文件版本、单元格、指标、期间、币种、单位、数值、公式和计算执行结果；重复绑定摘录使用 `excerptOmitted` 与 SHA256 标记。原始会话文件和完整回执没有修改。原文业务限定仍须依据已提供的原始文本或工作簿证据核验，不能靠摘要指纹批准。

审校与答文恢复仍使用同一个证据选择函数，工具来源和片段一致。证据包预算没有增加；本轮最大 147,745 字符，低于 150,000。此数值只指共享证据包，完整审校输入还包括报告、工作簿证据和状态文件，不能把它当作整个模型请求的大小。

### 3. 输入未覆盖与财务错误混在一起

修复：

- 明确关联的回执无法进入输入时，先返回审校输入缺口，不发起一个已知输入不完整的付费审校。
- 对结构化 `inputCoverageGaps`，以及有明确传递遗漏措辞、能对应实际遗漏工具/ID 的审校意见，归入输入限制，不要求删除事实。
- 同一句主张、同一证据仍存在同一输入缺口时，改写外围文字不会触发下一次审校。新来源、工作簿证据变化或主张变化会重新检查。
- 普通“缺少证据”、币种/期间/指标错误仍是有效金融问题，不能因为预算受限而一概豁免。
- 已关联的工作簿证据使用完整的 `cell:文件路径:单元格` 身份；不会把别的文件中的同坐标当成来源。

### 4. 每轮都重新尝试已经截断的审校方式

原记录前五轮都为 `reasoning:low → stopReason:length → reasoning:off`，第六轮一次返回；合计 11 次请求。

修复：同一个真实用户问答、同一模型共享审校策略。首次发生推理输出截断后，该问答后续审校直接使用已有的非推理 JSON 回退方式，不重复已知失败路径；新用户问答或模型变化重新建立策略。主问答仍使用原模型及推理配置。此策略不缓存金融批准结论。

按录制事件离线重放：六次报告审校需要的请求尝试为 `2、1、1、1、1、1`，合计 7 次。**11→7 是控制流模拟结果，不是修复后的真实模型性能测试，也不代表六轮报告审校会自然减少到一轮。**

### 5. 审校也会算错，修正建议必须核算

记录中审校将 `186,983−113,437` 写成 `69,546`，确定性计算结果为 `73,546`。原稿的 `69,023` 也不正确，且同时存在净利润/归母净利润身份混用。

修复：确定性检查审校理由中的明确算式，修正错误计算建议并保留原理由与修正轨迹。不会因此放行原稿，也不会清除有效的指标身份异议。本轮完整回放检测到并纠正这一处错误建议。

### 6. 独立指标错误继承前面的区块名称

原始查询出现 `Capex` 被标成 `Tax` 区块、有效税率/扣除股份支付的税项继承 `Interest income`。这种推断元数据又进入引用和审校，增加错误口径判断。

修复：扩充通用财务行识别，独立的资本开支、现金流、税率与带会计调整后缀的税项保留本行身份；产品行仍保留所属收入/毛利等区块。新查询、旧回执恢复、引用展开及审校工作簿证据使用一致的规范化规则，原始数值与公式不改动。

报告工具同时返回定位到原句的 `repairPlan`，要求同步修改受影响结论及状态中的同一 ID，保留其他有据段落。该反馈减少无目标的整篇重写，但不能保证模型每次都正确执行修订。

## 尚不能宣称解决的部分

1. 原稿中 TTM 与预测市盈率、基本与摊薄 EPS、新旧股本、净利润与归母净利润混用，以及报告/状态阈值不一致，仍需生成正确修订稿。离线回放不能替模型补写正确金融分析。
2. 审校的业务语义判断仍可能不稳定；本轮确定性修正只覆盖可明确解析的算式，不能自动裁定所有来源质量和投资推理问题。
3. 当真正必需的原始资料超过预算时，系统仍会给出审校输入不足，而非伪造完整通过；本轮没有实现无限容量的证据库或完整依赖图。
4. 本轮记录还有行情绑定使用非 Excel 定位符、证券名称后缀匹配、外部抓取超时等独立问题。未把它们混入本次审校循环修复，后续可沿通用工具合同另行处理。
5. 本次问答由用户主动取消，未产生最终报告交付。因此没有新的最终答文/页面/报告/状态一致性实测结论；已有交付链路回归通过不替代真实生成验收。
