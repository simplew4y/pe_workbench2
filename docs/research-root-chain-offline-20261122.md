# 投研主链路根因修复与离线验证

日期：2026-11-22。

本轮修改已落在本地工作区。修复了证据选择、部分指标身份、重复改写判断、校验热点及最终文件发布的共同机制，没有按公司、题目、目标价或特定单元格写豁免。

**机制回归通过，但不能宣称真实问答质量已经达标。** 使用旧模型答文和旧审校记录的完整回放仍为 partial；它无法代替修复后模型重新研究的结果，也不能用旧审校的“通过”免除新稿核验。

本轮没有调用付费模型，没有提交、推送、部署，也没有重启现有 8081 服务。HEAD 仍为 `3191b078fb23976ac67362aa242aa3faecf31618`。原有未提交修改保留。本轮开始前的工作区快照位于 `out/root-chain-repair-20261122/before/`，差异备份为同目录 `before.patch`。

## 1. 证据为什么会消失，以及实际改了哪里

原先审校与恢复答文各自按近期记录截取。随着网页、工作簿和重复草稿增长，较早的行情会被挤走。只把排序改成“相关词越多越优先”也不够：长工作簿天然包含更多相关词，仍能挤走短行情回执。

新增 `lib/research-evidence-package.mjs`，由审校、恢复答文和定向修订共同使用：

- 优先当前正文明确引用的来源 ID/URL，并为正文涉及的指标选择对应原始回执，保留可能纠正前一来源的另一份证据；普通词语相关度和时间只作为辅助排序。
- 不以数值相同作为关联依据。选择不是批准，最终仍检查主体、指标、期间、单位和上下文。
- 大段内容按完整段落/表格块节选，保留邻近限定语；不可安全容纳的块明确留在未覆盖目录，不从中截一个裸数字充当证据。
- 审校与恢复共享来源 ID、原文和截断信息；两种序列化形式都检查预算，默认上限仍为 150,000 字符。
- 目录记录原始回执哈希、原长、是否纳入、是否节选。目录只证明回执存在，不证明某个数值正确。
- `inputCoverageGaps` 将“本次审校输入未覆盖所需原文”记录成审校输入问题，不能伪装成数字错误或直接批准答案。
- 相同用户轮次中，保留已经建立的“原文段落 → 原始来源 ID”关联。只有文字不变的段落复用关联；修改数值后关联不再命中，整篇新稿仍重新审校。

接入位置：`lib/research-audit.mjs`、`lib/research-evidence-scope.mjs`、`lib/research-delivery.mjs`、`lib/research-review.mjs`。报告审校同时获得真实原问题。

## 2. 指标身份和数字校验

修复了三类身份混淆：

1. `Net profit, non-GAAP`、`Net income (IFRS)` 等带会计口径限定的叶子行，不再因为字符串识别失败继承前面的 `Interest income` 区块。引用展开沿用该行真实标签，不拼接无关区块制造新事实。
2. 整体市盈率与核心业务市盈率增加明确的估值范围区分；不能把核心业务倍数当成整体 PE 的应等数值。缺少范围信息仍须补核，不自动判对。
3. 表头、`COMMENT` 等非数值单元格不能成为未绑定数字的“正确值”。没有可支持的数值时报告缺证，不能声称数字应等于一个表头。

此外，原来的行情适配器只提取股价和市值。现在 `lib/market-evidence.mjs` 中的公共字段定义也覆盖年内涨跌幅、52 周高低点，并同时供证据选择与数字校验使用。正反向测试覆盖错误数值、年份、币种、主体、失败回执以及把下跌说成上涨；不是简单给这些数字放行。

这不是完整金融语义系统的重写。非标准简称、复杂分子分母、跨年假设继承和外部资料的会计口径仍需现有审校与来源绑定共同判断。

## 3. 性能和重复返工

`lib/financial-evidence.mjs` 原来在每个主张与每个候选来源的比较中重复构造指标别名和正则。现在按固定规则表预构造索引，并使用有大小限制的纯归一化缓存。没有缓存“主张已通过”结论。

在进一步改动指标语义之前，使用同一份真实草稿做了独立 A/B：

| 项目 | 修改前 | 仅归一化性能优化后 |
|---|---:|---:|
| 草稿字符 | 11,075 | 11,075 |
| 引用 | 2,788 | 2,788 |
| 工具调用 | 86 | 86 |
| `lintLedgerAnswer` 耗时 | 79,319.98 ms | 12,850.06 ms |
| findings / errors | 306 / 204 | 306 / 204 |
| findings JSON SHA256 | `a4c1f01d43083ab8dea27d85efb1da50f56ed247d5a56b5ed59ea312790eb5e0` | 相同 |

即该校验样本耗时降低约 83.8%，约 6.2 倍。**这是本地校验的测量，不是完整在线回答加速 6.2 倍的承诺。** 模型生成、联网取证和语义审校耗时没有重新测量。

新增 `lib/research-repair-progress.mjs`：正文审校和交付恢复按问题身份及原始证据判断是否有进展。周围文字改写、另一次报告写失败不算新证据；来源、主张或计算结果改变可以重新修订。同一实际用户轮次的内部修订不重置正文修订记录。对同一错误原封不动重复输出的测试，生成次数从初稿加两次修订降至初稿加一次修订，错误仍被拒绝。

报告原有的精确版本审校缓存继续保留。尚不能保证所有语义等价但表达不同的审校理由都归并为同一个问题，不能声称已经消除了全部多层返工。

## 4. 最终交付的一致性

保留原有原子发布、文件所有权、基线哈希、备份、回读和 manifest 校验，不通过放宽门禁发布监控。

- 最终发布不再自动在正文开头插入“部分完成”总括说明。
- 本次目标文件的旧保存声明由宿主最终回执替换；不删除其他文件的真实失败，也保留同段独立财务事实。
- 最终报告和状态 JSON 发布成功后，走与正常写文件相同的材料索引与广播回调。索引前再次核对发布哈希，避免将已变更文件当成刚发布的版本。
- 索引失败单独记录 `materialIndex.pending`，不谎称文件没保存，也不回滚已提交的研究文件。
- 裁剪以 Markdown 结构为单位处理空引导句、已失去前提的条件句、孤立子标题和残缺编号列表。相关缺口说明保留，但不放在全文开头；原文未发生裁剪时不重排用户原有章节和列表。
- 不从剩余正文猜测或编造观点、阈值、失效条件。状态与报告未同版通过时仍保留候选备份、关闭自动监控。

主要位置：`lib/report-publication.mjs`、`lib/research-document-closure.mjs`、`server/agent/report-materials.mjs`、`server/agent/session-service.mjs`、`server/create-app.mjs`。

## 6. 仍未解决或不能由本轮证明的部分

1. **旧记录的研究内容仍不完整。** 七节框架中的部分敏感性、观点台账与失效条件不能由现有通过记录完整交付。不能把 partial 改名当成 completed。
2. **报告与候选状态的语义对齐仍未通过。** 本轮解决版本和展示的一致性，没有用程序猜测缺失的 T/A/S/F 对应关系。最终状态中可跟踪观点为空、自动监控关闭是明确的剩余交付缺口。
3. **旧稿已经写错或裁掉的内容不能自动变成新研究。** 回放继续消费录制时的稿件、绑定和审校意见，不会调用一个“假想的新模型”补齐正确分析。因此保住审校输入并不等于旧录制答稿会自动恢复完整。
4. **复杂金融语义仍有未核项。** 比较口径、缺少可靠来源、元数据不全、阈值缺少推导，以及独立事实与依赖结论的边界仍存在。报告的完整性和行文效果尚未达到最终目标。
5. **极端证据预算与索引失败只显式暴露，不伪造成功。** 过大的不可安全分割原文会进入输入缺口；材料索引失败会留 pending。尚未新增后台自动补取或持久化索引重试任务。
6. **不能承诺在线总时延或新模型重写次数。** 本轮只证明确定性校验热点显著降低、相同问题的无效改写不再机械重复。未重新测量模型端耗时。
