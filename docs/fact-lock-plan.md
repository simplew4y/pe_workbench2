# 事实锁定开发计划

本文维护「追问补数」改动的开发顺序、分期范围、设计要点和验收口径。分析背景见 Google 文档[追问补数问题：分析与改法](https://docs.google.com/document/d/1kfRYNUtjqPQfhXxO0Puiny09L_uuwrMfcfg89-T_Y38/edit)。

- 更新日期：2026-11-11（Asia/Shanghai）
- 开发分支：`feat/fact-lock`
- 发布约定：不自动合并到 `main`，不自动上线。第一期可以单独验收、单独合并，不必等检索做完；是否合并须另行确认。

## 原则

不要推倒重来。现有台账、项目已校验结论、引用和回答后检查都留下，按三期改现有流水线。总体做法是挂进现有流水线，不另起一套知识库。会话台账继续作为已核数字的登记处，项目已校验结论继续用现有的状态文件。主题索引和数字登记分开：小模型只维护主题和摘要，数字权威始终来自登记，不来自摘要或旧回答。

建议顺序：先做自动登记和无出处拦截，先收住成批补数；再做主题索引和两层检索；最后跑对照回归。

## 第一期：自动登记和无出处拦截

这是根因修复，做完就应能收住成批补数，可以先单独验收、单独合并。

### 要做的事

先补系统自动登记。现在台账已经能记事实、主张、更正和待核项，但已核数字主要靠模型自己「记一笔」，工具查到的结果不会自动进去；用户纠正目前也只先记成主张，不会立刻变成生效的已核事实。改成：每一轮工具成功返回时，由系统直接写入，不从答文里抽数字。写入范围包括读到的单元格或页面、计算和单位换算结果、带获取时间的行情、校验通过的框架结论，以及用户的明确纠正。用户纠正要马上生效，旧值保留可查，不能悄悄只留新值；两处来源打架时两边都留并标注。锁定里没有的新数必须先查再写。文件已更新，或用户问「现在」「最新」时必须再查，旧锁定值不得当作当前文件值；现价不得用缓存冒充实时价。框架结论进项目级，本轮查到的数进本会话；其他会话里未核验的问答不能当事实入库。原来的「记录台账」仍可用于主张和待核项，但已核数字不再依赖模型主动去记。

再升级回答后检查，这一步用完整登记做对照，所以放在自动登记之后。新增两条：没有出处的关键数字要拦；位置被删掉时，只靠它撑着的数字一并处理，并取消现在这句「不要改任何数字」。已有的纠正回退、单位、数量级和百分比检查继续保留；仍然是软警告，自动改最多一次。可点击出处仍只能来自本轮真正查到的结构化结果；追问要用已锁定的数并显示出处时，由系统按登记再带上，禁止从答文里猜坐标。

提问前这一期可以先把本会话当前已核数字完整带入，先不做主题检索。

### 设计要点

1. 把行情工具的返回补成结构化结果。成功时应带上代码、价格、币种、行情时间和获取时间；失败则不写入。不能从答文里猜现价。
2. 工具成功返回时由系统自动登记。入口挂在回答后处理：工具成功结束时写入，回答结束前再扫一遍本轮成功结果，避免漏记。只接受工作簿和页面读取、计算和单位换算、结构化行情、校验通过的框架结论。计算类结果可以登记派生值，但只有带着上游出处时才能生成可点击引用。失败结果、答文里的数字、其他会话未核验问答都不能写进去。同一绑定、同一来源的新值取代旧值，历史保留；两个可靠来源数值不同则两条都留并标冲突。文件版本变了，旧锁定值不得再当当前文件值。用户明确纠正要立刻写成生效更正。
3. 升级回答后检查，对照完整登记，而不是提问前那一小段摘要。现价若已跨日，或用户在问「现在/最新」但本轮没有成功查行情，要拦，不能把登记里的旧价说成现价。
4. 可点击出处的还原。若追问用到已锁定且出处身份完整的数（材料、版本、位置、数值都在登记里），由系统按登记带进本轮引用；若版本已旧，或再读后数值对不上，则不能还原，必须再查。答文里写了位置但登记和本轮工具都没有，不得因此生成可点击项。上一轮出处不能直接满足本轮位置检查，除非本轮由系统按登记正式带入。

### 怎么验证

- 行情解析：用固定返回做解析单测，成功必须抽出代码、价格、币种、行情时间和获取时间；失败或残缺不能登记。现有「不得用缓存价冒充实时价」的测试保持通过。
- 登记单测：覆盖写入、取代、冲突、过期、版本失效、纠正立即生效，以及「答文里的数字不能写回登记」。用假会话跑「本轮工具成功 → 台账已有记录」，以及「只出答文、不跑工具 → 台账不变」。旧台账文件仍能读，现有台账和主张测试保持绿。
- 答文检查：在现有测试里加无出处关键数字、删除无效位置后留下裸数字、过期现价、纠正后仍复述旧值这些固定文本用例，不需要调用大模型。再用假会话确认：会触发一次修正；修正提示不再要求「不要改任何数字」；第二次不再自动改。这些用例可用预先放好的登记，不必等主题索引。
- 出处还原：身份完整且数值一致时，本轮引用里出现该出处；版本过期或数值不一致时不出现。
- 还要确认：第一轮工具查准的数，第二轮不能另编一个；可点击出处只来自本轮结构化结果；现有计算工具和盯盘自动会话保持原样。

第一期已完成上述开发与修补。补修了两处验收漏洞：用户纠正后的新值要进入登记，避免被误标为无出处；已有出处的数字不得被误标为位置被删后的裸数字。

## 第二期：主题索引和两层检索

第一期稳住数字之后再做，用来改善省略主语、切换话题和口语定位。不动第一期已经稳住的登记和检查。

### 要做的事

先加一层主题索引，交给小模型维护。它只整理主题、摘要，以及指向已核内容和相关问答的索引，不把数字写成权威，摘要也不是新证据。写入时用确定性检查：摘要里若出现登记中没有的关键数字，这次更新作废。对话模型只读，禁止把自己的回答写回记忆；对话模型没有主题索引或已核数字的写入口。原来的「记录台账」只保留主张和待核项。

然后改提问前的带入方式。现在只塞一小段提示，台账也只带很少几条，普通追问不会自动带上已校验结论。改成两层检索：先根据当前问题和对话历史找主题摘要（第一层只看主题编号和摘要、历史和当前问题，不看第二层的具体数字），再取出对应的已核内容、冲突项、来源已过期项和相关问答，交给对话模型。检查仍对照完整登记：某条已登记事实没有被带进本轮提示，不能因此被标成无出处。同一项目新开的对话，自动带上最新已校验结论。锁定里没有的，或已经过期的现价，必须再查。第一层定位本身不做加减乘除，算差仍走现有计算工具。盯盘自动会话的写入路径保持原样。

小模型与对话模型分开配置，避免索引模型和答题模型混用。

### 怎么验证

- 主题检索用固定索引单独测，对应模糊、省略、歧义、切话题后再问的用例（R01–R04，固定主题 W01–W04）。只看有没有找对主题、有没有取到对应内容，和最终答得对不对分开记，避免把口误理解算到记忆头上。
- 固定夹具使用 A/B 两家公司的营业收入与利润数字（A 公司 2024/2023 年营业收入 120/100、归母净利润 15/12、合并净利润 17/14；B 公司营业收入 80/50）。这组数字不能与「无出处基数」用例里故意不同的基数混用。
- 摘要里塞一个登记没有的数字，更新必须被拒绝。
- 用契约测试确认对话模型没有主题索引或已核数字的写入口。
- 定位函数必须可注入，以便确定性测试不依赖在线模型。在线小模型定位是可选测试：没有密钥时不得让持续集成失败。
- 现有的系统回归和可点引用测试必须保持通过。

第二期实现已包含主题索引模块、提问前两层检索，以及 `test:topic-index`、`test:topic-retrieve-live` 脚本。正式验收仍待交卷后由 Chief 复验，再安排独立验收。

## 第三期：对照回归

原则上不再改产品逻辑，只跑样例、记对比、补漏。

先看专业问法和口语问法是不是被理解成同一需求；再用同一批多轮案例对比改前改后的最终回答。把专业对口语的单轮、以及同一批多轮案例，先在现行代码上跑出基线，再在新代码上跑，比较最终回答。

评分看：数字能否追溯到出处（回到登记或本轮工具结果）、是否绑对了公司、科目、年份、币种和单位、纠正和时效是否生效、计算和定性是否一致、指代有没有指错、位置和主张是否还对得上。节点命中率和回答正确率分开记，并记录通过率、事实是否被找回、多查了几次、时延变化。

构造样例时，不同案例里故意不同的基数不要混用。样例里的标准答案和未查询工具结果只给评测用，不能在对话过程中泄露。

语义张冠李戴、非主张数字、定性对错、过期缓存被冻进锁、一次自动改没改完、抽取漏检、判断或情景类问题，仍允许以个例出现，但不能再成批出现。第一期验收通过后，不应再成批出现无出处补数。
