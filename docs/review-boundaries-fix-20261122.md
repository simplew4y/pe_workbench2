## 修复范围

| 项目 | 原因 | 本次通用修复 |
| --- | --- | --- |
| R1 算术纠错误放行 | 只凭相同数字或一段中的正确算式，就撤销整个审校问题；金额回执也可能被当成小数比例 | 仅处理 `numeric_units` 的单个具名数值主张；要求成功回执、名称匹配、确定性复算和明确单位。复合摘录、口径争议、金额与比例错配、历史 `%` 标签歧义均不自动放行。使用本轮审校可见范围内的回执，并向审校提供同一份有界回执集合。 |
| R2 纠错后审校状态不一致 | 删除问题并更新 checks 后，`ok` 仍保留原来的 false | 有效审校结果在裁决后同时重算 `issues / checks / ok`。协议不完整、其他未解决问题和确定性硬错误仍阻断交付。保留被推翻意见、证据 ID 和结果索引以便追溯。 |
| R3 一处证据不足导致全文结论误删 | 使用全文统一的 contaminated 标记，无法区分独立章节与依赖结论 | 根据原始 Markdown 章节层级、局部前提、明确主体引用和全局总结确定依赖范围。保留独立章节结论；跨章节引用被拒前提、无独立前提的结论章节和全局结论仍受约束。被拒绝的结论段整体处理，防止删开头、留后续推断。明确披露缺口的研究步骤不当作财务结论。 |
| R4 新版本计算误抵销旧版本失败 | 比较重试参数，遗漏实际成功回执中的版本；缺失版本被当作通配符 | 比较成功结果实际读取的 bindings，同时校验重试声明。旧请求明确指定版本时，实际成功回执必须给出相同版本、材料和位置；版本缺失或改变不算恢复。显式工具失败优先于 success 展示标记。 |
| R5 用户可见更正被当作内部修订删除 | 以“更正/订正/修正/勘误”开头就删整段 | 根据正式交付历史和用户请求区分公开更正与内部标签。公开更正和历史不明的更正保留。已知首轮且用户没有要求更正时，只移除过程标签，保留通过检查的事实正文。历史旧会话缺少交付标记时按未知历史处理。 |
| R6 合法小百分数丢失单位 | 根据结果绝对值小于 1、算式是否含 100 来猜测编码 | 单位标签按声明解释；`0.8-0.3` 的 `%` 输出仍是 `0.5%`。新增可选 `ratioEncoding` 明确 fraction / percentage_points，与单位冲突时明确报错；实际换算使用 `fromUnit/toUnit`，不自动乘 100。 |

这些规则位于公共计算、审校、失败恢复和答文交付链路，生产代码中没有题号、公司名或历史答案特例。测试中的公司、数据和旧记录只作为验证材料。

名称与数值绑定只证明本次算术裁决的对应关系，不代替主体、期间、来源和经济含义的完整审校。无法可靠绑定的旧回执继续交由审校处理，不因“数字看起来一样”消除错误。
